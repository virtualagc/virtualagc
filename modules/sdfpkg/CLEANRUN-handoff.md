## obj-sections.py and csect-collisions.py, 2026-08-14

`obj-sections.py --keep=F | --dass=F OBJ... --out-dir=D` re-emits an object
module carrying only the sections named.  ESD and RLD cards are rebuilt from
their filtered entry lists; TXT, SYM and END are copied byte for byte.

    ESD IDS ARE NEVER RENUMBERED, because TXT, RLD and END all reference
    sections by id and every renumbering mistake would be silent.  Kept
    entries keep their ids and the ESD cards are emitted in runs of
    CONSECUTIVE ids -- a card stores only its first id and the reader assigns
    the rest positionally, so a run is the unit that can be encoded.  Gaps
    between runs are fine: every consumer looks an id up.

    A DROPPED DEFINITION THAT SOMETHING STILL NAMES BECOMES AN ER of the same
    name and the same id.  This is the part that makes it work.  #ZDPLLIG is
    four bytes pointing at #CDPLLIG, and the pointer must go on saying where
    that code lives in the configuration that loads it; deleting the RLD
    would leave the ZCON unrelocated.  As an ER the address comes from the
    CSECT table, which publishes it for exactly this case.  Verified on
    DPLLIGHT.obj: 6 ESD entries become 2 -- `ER #CDPLLIG`, `SD #ZDPLLIG` --
    with the ZCON's TXT and its one RLD intact.

ABSENCE FROM THE MEMORY MAP IS NOT SUFFICIENT EVIDENCE, and using it alone
costs real agreement.  dass-syms.py's own note says 79 map-absent sections
MATCH the dump across the eight configurations, 59 of them verifying content
the --no-data patterns do not cover, up to 477 halfwords in SSW's #DDCDDG3.
Measured: withholding every map-absent section cost SSW 27 sections that had
all been OK.

## THE CRITERION IS NOW THE SITE, NOT THE MAP  (dass-fields.py --mark)

The user's reframing, and it is the right one: the test is not whether the
reference resolves to THE symbol named, but whether it resolves to ANYTHING the
dump corroborates.  Overlaid sections need not even share names -- #DDG9LIG and
#DDPLLIG do not -- so name identity was never the question.  Resolve
everything, then read the site:

    the image holds what resolution produced   -> the build resolved it, and a
                                                  match against any known
                                                  symbol's address is a match.
    the image holds an unpatched address field -> the build left it alone: MARK

`dass-fields.py --mark=LINK.json:DUMP.fcm`, where LINK.json is an UNMARKED
full-configuration link.  It lives there and not in dass-syms.py because the
evidence is read at references to a section's FIELDS, and `contents` -- the
field names -- is what dass-fields.py itself adds, after dass-syms.py has run.
Marking in dass-syms.py saw no contents and marked nothing.

    ONLY UNAMBIGUOUS RELOCATIONS VOTE.  `target` is the 32-bit word at
    `address` for ACON (0x1C, 0x9C) and the halfword there for YCON (0x00,
    0x80); 0x10, 0x50 and 0xD0 patch register fields or sector-encoded halves,
    where `target` is not what gets stored, so they are skipped.

    0000 COUNTS AS UNPATCHED HERE and must NOT be added to dass-syms.py's FILL.
    The votes pass asks what address a site implies, where 0000 is a possible
    answer; this asks whether an address was written at all, where it is the
    answer "no".  G9's TFCMPFD1/2 are 0000 in the RAW scrape, not C9FB, so the
    listing states them.

## WHAT AN "ANY MATCH" TEST WOULD COST IN fcmcmp, MEASURED

The user's framing, and it is the right one: we cannot test "the toolchain
produces exactly the right halfword everywhere", because which overlay was
resident is not knowable without the CON80 layout.  What we can test is whether
it ever produces a WRONG halfword.  Under that framing an "any match" rule is
not a weakening -- it removes false positives that assert something we cannot
know.

AN EXISTENCE TEST IS ENOUGH AND IT NEEDS NO NAMES: a set of addresses at which
some configuration's symbols live, buildable from the csects-*.json already on
disk (8649 addresses over all configurations).  Since it carries no names,
nothing about the symbol table lnk101 writes is touched, which was the original
objection to the whole idea.

    MEASURED ON G9:  12425 differing halfwords, of which 2772 sit on an
    address-constant relocation -- the only ones the rule can touch -- and
    BOTH values are known symbol addresses in 28 of them.  Small enough to
    list and review.

    IT LEAVES THE SYSTEMATIC RESIDUE ALONE, which is the point.  $0SPSPSP and
    friends differ as ours A850 / dump A855, ours A86E / dump A874, ours A84E /
    dump A851 -- one consistent small offset on TFIVPS22, repeated over many
    sites, which is a real candidate defect and is not excused.  It DOES catch
    FCMBMTG9's TFIVPF12 (F941 against F921), the case 259-260 already flagged
    as genuinely ambiguous.

    ONLY ADDRESS CONSTANTS CAN BE AMBIGUOUS.  An AP-101S instruction reaches
    memory through a base register and a displacement and never carries a full
    address; the relocations that touch instructions patch REGISTER FIELDS
    (0x10, 0x20, 0x40, 0xD0), four bits at a time.  A full address lives only
    in a DC -- YCON, ACON, ZCON -- so the flag byte identifies exactly the
    halfwords the rule may consider, with no need to reason about surrounding
    code.  This is the same restriction dass-fields.py --mark already applies.

    A CONSUMER OF --dump-diffs MUST FILTER C9FB/C6C6 ITSELF: it emits the
    no-reference-data halfwords (148 in G9) that the counts exclude.
    Consistent with the flag being documented "no elision", but it will bite.
