(The `DO UNTIL LEVEL < 0` in ENTER_SDF_TEMPLATE had been rendered correctly as `while LEVEL >= 0`, so this was not a systematic misreading -- these two were simply wrong. They were the only three DO UNTILs in the module.)
- SDF_REPL_ARG_NAME: `STRING(SDFPKG_LOC_ADDR+SDF_F(1+i))` passes xplBuiltins' STRING() a *string descriptor*, not a string, and needs the inverse of MAKESTRING. Added STRING_AT(), decoding length-1 from the top byte and the address from the low three, with the all-zero-descriptor-is-empty special case. The relative address in SDF_F is relocated by adding SDFPKG_LOC_ADDR before decoding; the length in the top byte survives the addition because addresses are 24-bit.
- New fixtures in modules/sdfpkg/tests/: FUNCA.hal/USEF.hal (FUNCTION comsub, two parameters), PROCA.hal/USEP.hal (PROCEDURE comsub with an ASSIGN parameter), COMPM.hal/USEM.hal (COMPOOL carrying three REPLACE macros, one of them parameterized, all actually expanded by the user program). Note for future fixtures: multiplication in HAL/S is juxtaposition, `A B`; `*` is cross product and gets you error E4.
- invariant.py strengthened twice. It now compares the flag bits of each symbol's leading cross-reference entry rather than simply exempting SYM_XREF -- the index into the cross-reference table legitimately shifts, because including a TEMPLATE inserts source that is itself cross-referenced, but the flags must agree, and they do. And it now requires the --sdfi run to report "INCLUDED FROM SDF" while the other run does not: without that, an SDF route that quietly fell back on the template would agree with the template route trivially and pass.
- Results: USEA 15 symbols, USEF 7, USEP 8, USEM 10 -- identical either way in every case. Regression unchanged: 99-source sweep byte-identical to baseline, cmem 77, sdfpkg 4126.
